Architecture recommendation · 2 October 2026

Ambitious product. Honest boundaries.

This blueprint plans the full product while keeping the first release achievable. Free local infrastructure and limited API use are realistic. Unlimited free public operation and guaranteed Perplexity-level research quality are not established.

Reading path: review the stack and architecture first; use the 52 sections as implementation specifications, then apply the roadmap and release gates. This is a design artifact—not an implemented application.

SECTION 01Product definition

ARES — Autonomous Research & Evidence System. A personal, evidence-led research application that discovers sources, reads them, compares claims, and produces answers with inspectable citations. Gemini provides language understanding and synthesis; ARES owns retrieval, provenance, budgets, state, and evaluation.

The initial audience is an independent researcher or developer running ARES on their own computer. A public service is a later product decision. This document freezes recommended architectural boundaries, not a claim that the software has been implemented, benchmarked, secured, or proven equivalent to Perplexity.

DecisionScope
Deliver nowA complete design and development blueprint. No repository creation, product implementation, deployment, or paid subscriptions.
Build firstOne reliable, cited research loop; a polished search interface; inspectable evidence; durable runs.
SuccessA fresh checkout can run a labeled offline demo without keys, and a configured live run can answer supported questions with traceable evidence.
Explicit exclusionsFull commercial feature parity, unrestricted autonomous browsing, arbitrary code execution, guaranteed free public hosting, billing, image/video generation, and enterprise connectors.

SECTION 02Product principles and cost reality

  • Evidence before eloquence: a concise answer with gaps exposed is better than a polished unsupported report.
  • Bounded autonomy: the model proposes research steps; deterministic policy approves tools, URLs, permissions, and budgets.
  • Free-first: use open-source local infrastructure and eligible API allowances. Zero mandatory subscription is achievable; hardware, electricity, internet, and unlimited API capacity are not free.
  • Own identity: reproduce familiar search, thread, and citation interactions with ARES branding and original assets.
  • Simple deployment boundary: a static frontend, an API, one worker, and PostgreSQL. Add browser isolation only when needed.
Strict free mode: do not activate billable providers or automatically switch to paid models. If a quota is exhausted, pause or return a partial result. A local usage counter cannot guarantee zero billing if the provider account itself has paid billing enabled. Use an eligible free-tier project and verify the account settings.

Google documents model-dependent free access and project-level rate limits. Google Search grounding is not a universally free substitute for a search provider. Unpaid-service data treatment also matters: avoid sending confidential documents through a free cloud model without a suitable policy and informed consent. [1] [2]

SECTION 11Why these choices—and what to defer

  • React + Vite: focus engineering effort on search, streaming, citations, and accessibility. A static web build simplifies later hosting.
  • Python: one backend ecosystem for parsing, retrieval, model calls, and evaluation. CPU-bound parsing runs in a worker process, not the API event loop.
  • PostgreSQL: one authoritative store for runs, jobs, evidence, and user data. Shared SQL transactions are valuable before distributed services.
  • Official Gemini SDK: direct access to supported model features without forcing every task through an agent framework. [5]
  • Do not add Redis, Kafka, Kubernetes, Neo4j, Qdrant, a separate auth service, a model gateway, or ten MCP servers without a measured need.
  • Do not fine-tune an LLM, train an embedding model, or crawl the whole web. Improve retrieval and evaluation first.
  • Do not call any self-check “verified truth.” Store what evidence supports a claim, including contrary evidence.
Jev decision: deferred experiment. TypeSafe describes Jev as a structured decision model rather than a prose generator, with metered API pricing. That may fit routing or ranking, but does not replace Gemini synthesis, source discovery, or evidence storage. No proven ARES quality gain or required free allowance has been established. Benchmark a bounded adapter against deterministic routing and Gemini before adoption; do not infer open weights or service availability from open-source client examples. [6]

SECTION 12Overall system architecture

SECTION 13Research engine architecture

Use a typed finite-state workflow: QUEUED → PLANNING → DISCOVERING → READING → EXTRACTING → CHECKING → SYNTHESIZING → COMPLETED. CHECKING may return to DISCOVERING when a material gap remains and budget permits. Terminal alternatives are PARTIAL, FAILED, and CANCELLED. Persist transitions before emitting events.

StageInput → outputDeterministic boundary
PlanQuestion + scoped history → subquestions, source requirements, date window.Validate schema; clamp all model-suggested limits.
DiscoverSubquestion → ranked candidate sources.Deduplicate, enforce scope, reserve tool budget.
ReadApproved candidates → versioned documents.Safe fetch, content limits, parser quality checks.
ExtractRelevant document sections → evidence packets.Every quotation must match source text at its stated location.
CheckCandidate claims + evidence → support status and gaps.Validate IDs, source independence, scope and date alignment.
SynthesizeChecked claim set → answer blocks + citation references.Render URLs only from stored source records; reject invented references.

Parallel research tracks are bounded tasks, not personalities. Each returns {subquestion_id, source_ids, evidence_ids, tentative_claims, gaps, errors, usage}. Only the coordinator synthesizes the answer. The first working loop uses one research wave; V1 adds at most three.

Model-facing intermediate reasoning is not a UI feature. Show brief action summaries, retrieved sources, and evidence decisions; do not stream hidden chain-of-thought.

Prefer deterministic parsing for explicit modes, supplied URLs, upload IDs, and dates. Use one structured Gemini call only for genuinely ambiguous decomposition. “Today” resolves in the user timezone; “as of 2024” cannot silently use later discoveries as contemporary evidence. Unknown publication dates remain unknown.

Example: “Compare current agent-memory approaches” becomes technical + academic, a recent date window, method/evaluation/limitations facets, and official repositories for implementation claims. A document-only request cannot silently widen to the web.

Filter before ranking: capability match → enabled adapter → authentication available → policy permission → quota reservation → source fit → latency/health score. The model names a capability and typed parameters, never a raw HTTP client or shell.

Tool output is data. Validate schema, size, IDs, URLs, and timestamps before any model sees it. Source authority is contextual metadata, not a universal trust score: a vendor is authoritative about its own release date, not automatically about comparative quality.

  • Registry is checked-in configuration plus typed adapter classes; no install-from-prompt or arbitrary plugin URLs.
  • Each adapter has contract fixtures for success, empty results, 429, malformed response, and timeout.
  • Adapter output carries provider name, request hash, retrieval timestamp, license/access metadata where known, and completeness.

SECTION 17MCP architecture

MCP is an interoperability edge, not the internal orchestration engine. MVP and V1 use native interfaces. V2 may expose a single read-oriented ARES MCP server with search_sources, get_evidence, and get_run; starting a research run requires an explicit capability and budget.

  • Inbound: map authenticated principal and scopes to the same application services as REST; never trust supplied tenant IDs.
  • Outbound: administrator-approved servers only; snapshot tool schemas, validate changes, apply output limits and timeouts.
  • Use separate credentials per integration; never pass through another service’s token as general authorization.
  • Local stdio is suitable for an intentionally installed local integration. Remote HTTP requires its own authorization and origin/security controls.
  • Do not expose filesystem, unrestricted browser, shell, or secrets tools through ARES. Follow the current MCP security guidance before enabling remote integrations. [7]

SECTION 18Browser architecture

V2 fallback: Playwright renders public, permitted pages that ordinary HTTP extraction cannot read. Use one fresh non-persistent context per task, a restricted worker identity, and a hardened container or stronger sandbox. Browser contexts isolate cookies; they are not a security boundary against a browser exploit.

SECTION 19Search and web architecture

Default: self-host SearXNG as a separate local service, enable its JSON output explicitly, keep it off public interfaces, and use only engines consistent with their terms. It is metasearch, not an owned web index. Availability and result quality depend on upstream engines; do not depend on free public instances. [9]

StepImplementation choice
DiscoverQuery variants from plan; request a small result set per subquestion; preserve rank and snippet as discovery metadata.
NormalizeRemove fragments and known tracking parameters without destroying meaningful query parameters; normalize DOI/arXiv IDs separately.
SelectPrefer primary sources and diversity; avoid counting mirrored or syndicated content as independent support.
FetchHTTPX through SafeFetcher; identify client; respect robots/access policies; per-domain concurrency and conditional requests.
ExtractTrafilatura for readable HTML, then quality scoring by text length, boilerplate proportion, and topic overlap; pypdf for text PDFs.
StoreCanonical source + immutable content version + retrieval event. Snippets stay distinct from full-text reads.
RecoverBlocked/empty → alternative source; low text quality → optional browser; no fabricated page content.

Gemini Search grounding is an optional adapter, disabled in strict-free defaults. If enabled later, preserve provider attribution and comply with grounding display requirements; distinguish provider-grounded support from ARES-extracted passages.

Pipeline: search → DOI/arXiv/title-author-year dedupe → choose canonical work → preserve preprint and publication separately → retrieve permitted full text → extract contributions, methods, evaluation, and limitations → connect implementations. Never infer paper conclusions from citation counts. A retracted/corrected status should be stored when the provider supplies it; missing status is not assurance.

Rate settings belong in provider configuration, with response-header handling. For arXiv, start with one request at a time and at least three seconds between requests, then check the current terms for the endpoint. No full corpus download or uncontrolled recursion.

SECTION 21News architecture

V2 starts with an explicit allowlist of RSS/Atom feeds, public company newsrooms, and official announcements. GDELT is a discovery experiment, not a necessary dependency; validate current endpoints, coverage, and limits before adding it.

  • One daily scheduler job per feed, plus on-demand freshness fetch; persisted watermark and idempotent source/version upsert. A daily job requires the local machine to be running.
  • Deduplicate canonical URLs, exact hashes, then near-duplicate text. Cluster event candidates by entities, event time, and semantic similarity.
  • Store story_cluster_id and upstream attribution. Twenty rewrites of one press release count as one origin, not twenty independent confirmations.
  • Keep publication, update, retrieval, and event timestamps separate; show date uncertainty and timezone.
  • Choose a bounded number of primary and independent secondary sources; distinguish statements, reporting, and independently established facts.
  • A live news answer must report its retrieval cutoff. If fresh search failed, say so instead of relabeling a cached answer as current.

SECTION 22Wikipedia and Wikidata

Use Wikipedia for orientation and Wikidata for entity identifiers and structured links. These are starting points; consequential or disputed claims should be checked against original sources. Use API access with a descriptive user agent, cache responsibly, and respect current API etiquette. [13]

  • Wikipedia adapter returns page ID, revision ID, language, URL, text sections, and retrieval time. Citation points to the exact revision when possible.
  • Wikidata adapter resolves QIDs and bounded property queries. Avoid arbitrary model-generated unbounded SPARQL.
  • Preserve language and disambiguation candidates. Identical labels are not proof of identical entities.
  • Record attribution/license obligations for reused content. Do not ingest entire knowledge graphs for the MVP.

SECTION 23GitHub and software research

V1 adapter reads public repository metadata, release/tag lists, selected documentation, manifests, and license files. Store repo owner/name, requested ref, resolved commit SHA, retrieval time, and API version. Use an optional read-only credential held server-side; respect primary and secondary rate limits. [14]

  • A recent commit is a maintenance signal, not proof of maturity, production adoption, or security. Count stars only as discoverability context.
  • Differentiate the core package from monorepo CLI/plugin releases. The latest-release endpoint is not a reliable package-version resolver by itself.
  • Use tags or package registries when repositories do not publish releases. A 404 for latest release does not mean the project is abandoned.
  • Never execute repository scripts or install dependencies to answer a research question. Read manifests as untrusted data.
  • Package-registry adapters resolve exact version, release date, repository link, and license metadata; cross-check the source license before claiming compatibility.

SECTION 24RAG architecture

V1 ingests user documents and selected reusable research sources. Live web research still fetches current pages; a vector index is not a freshness mechanism.

Model card limits make MiniLM an economical English baseline, not a universal multilingual recommendation. Evaluate a multilingual embedding model before promising Hindi or other language parity.

SECTION 25Knowledge graph strategy

Represent links relationally: entities(id, kind, canonical_key, label) and relations(from_id, predicate, to_id, evidence_id, confidence_label). Supported predicates include authored_by, cites, implements, studies, uses_dataset, and proposes_method. Each extracted relation needs provenance.

  • Use SQL joins and bounded recursive queries for citation trails and paper-to-repository paths.
  • Do not infer implements from a shared keyword; require README/paper evidence.
  • Delay graph-wide entity resolution and graph databases until real path queries or scale exceed measured relational performance.
  • Treat automatically extracted links as candidates; resolve DOI, ORCID, repository URLs, and Wikidata IDs with deterministic identifiers where possible.

SECTION 26Evidence architecture

Evidence {
  id, tenant_id, run_id, document_version_id, retrieval_event_id,
  text, text_hash, locator_kind, page, section_path,
  normalized_char_start, normalized_char_end, source_offset_map_ref,
  extraction_method, captured_at, access_level, completeness
}
ClaimEvidence {claim_id, evidence_id, relation, rationale_summary}
# relation: supports | contradicts | contextualizes

An evidence span must match the stored normalized document version. Preserve a normalization map to original text or use a page/section locator when exact source offsets are unavailable. Never pretend an HTML character offset is a stable live-page anchor.

Immutable content hashes allow citations to remain inspectable after a page changes. Store only permitted content with a defined retention policy; hashes and small excerpts do not remove publisher rights. Private uploaded content remains scoped to its owner and is excluded from shared caches.

SECTION 27Claim verification

StateMeaningUI wording
SUPPORTEDAvailable evidence directly supports the scoped claim.Supported by these sources
PARTIALLY_SUPPORTEDSome clauses or scope remain unsubstantiated.Partly supported
CONFLICTINGRelevant evidence supports incompatible statements.Sources disagree
INSUFFICIENT_EVIDENCENo adequate passage or coverage.Not enough evidence

First validate quotation identity, entity, date, unit, and numeric comparisons deterministically. Then use a separate structured model call where entailment is ambiguous. Same-model self-review is correlated evidence, not independent verification. Store checker/model version and short rationale, not an invented calibrated probability.

  • Classify conflict as direct, temporal, scope, definition, or apparent. Try to resolve scope/date mismatches explicitly.
  • Seek independent primary evidence for material disputed claims. Syndicated reports and papers citing each other are not necessarily independent.
  • If unresolved, include both positions with dates and sources. Remove unsupported assertions from the final prose or label them as hypotheses.

SECTION 32Event and job architecture

API creates run + queued job + run.created event in one transaction. Worker claims eligible jobs using a short transaction with row locking and SKIP LOCKED, writes a lease token and expiry, then performs external work outside the transaction. Start with a 30-second lease and 10-second heartbeat; tune from observed task behavior.

  • Every step checkpoint and corresponding event commit together. Sequence numbers allocate under a per-run transaction lock.
  • Lease token fences stale workers: every checkpoint write verifies the current token. Expired work can be retried, but old workers cannot overwrite newer results.
  • Delivery is at least once. Uniqueness keys prevent duplicate artifacts and logical steps; remote LLM requests may still duplicate if a crash occurs after execution but before persistence. Reserve retry budget for that possibility.
  • Cancellation is durable. Workers check it before every external call and between chunks; abort local requests where supported, then mark CANCELLED. Already accepted remote work may still consume quota.
  • After repeated transient failures, dead-letter the job with its last safe checkpoint. Recovery is explicit and observable.
  • Postgres notifications are a wake-up optimization only. Polling stored jobs/events remains the recovery mechanism.

Queue when admissible, otherwise reject with a reset/retry message. Retries consume budgets too.

  • Retry only transient failures: honor Retry-After, exponential backoff with jitter, at most two attempts beyond the first when budget permits. Do not retry 401/403 blindly.
  • Circuit breaker per provider after repeated failures, with a bounded half-open probe.
  • A step deadline cannot exceed the remaining run deadline. The last synthesis call gets a reserved budget.
  • If the remaining budget cannot support a final answer, produce a deterministic partial evidence summary.
  • Provider capacity is shared by project, not solved by issuing another key. Reset rules come from provider policy, not the user’s local midnight. [2]

SECTION 45Benchmark strategy

Start with 50 development questions and 50 held-out questions across ten categories: factual, current, academic, multi-hop, comparison, news, software, documents, conflicting sources, and historical/time-bounded. Add separate security fixtures and a small multilingual exploration set; do not claim multilingual readiness from English scores.

  • Each case includes query, scope/date, acceptable answer facets, relevant source passages, required citations, forbidden unsupported claims, fixture license, and annotation rationale.
  • Run deterministic frozen-source tests for regression and a separate timestamped live-search benchmark for freshness; never mix their numbers.
  • Compare: direct Gemini without retrieval; search-snippet synthesis; lexical retrieval; hybrid retrieval; full ARES with evidence checks. This shows whether added complexity helps.
  • Annotate a subset twice and adjudicate disagreements. Report sample size, failure count, abstentions, latency percentiles, token usage, hardware, model ID, and config hash.
  • A model change or provider search change requires a new evaluation snapshot. Do not put aspirational metrics in README badges.

SECTION 52Final architecture and implementation handoff

Build ARES as a Gemini-first, evidence-led modular application with a React frontend, FastAPI API, durable Python worker, PostgreSQL, local file storage, self-hosted search, and optional isolated browser. Start with the smallest complete research loop. Grow by measured retrieval quality and real user needs.

Before product implementation, accept the design baseline and run the compatibility/capability spike. A coding agent should implement one milestone at a time with a working UI, fixture tests, and documentation. It must not scaffold all future adapters as pretend functionality.

Implementation handoff brief:
1. Read the ARES blueprint and accepted ADRs.
2. Create only the milestone scope selected by the maintainer.
3. Resolve compatible dependencies; commit lockfiles and .env.example.
4. Build the smallest end-to-end slice with fixture providers first.
5. Add real provider integration with server-side secrets and quota limits.
6. Keep evidence IDs, document versions, ownership and events explicit.
7. Add meaningful contract/integration tests for the changed behavior.
8. Report working features, tests, remaining limitations and exact setup.
9. Do not deploy, enable billing, execute retrieved code, or invent metrics.

First implementation milestone: local app shell + conversation/run API + Postgres job/event persistence + replayable SSE + fixture-based answer with a functioning citation drawer. Then add live safe search and Gemini. This gives a reviewable product immediately while protecting the architecture.
