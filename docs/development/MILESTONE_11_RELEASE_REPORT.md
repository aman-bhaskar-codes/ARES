# Milestone 11 Release Report — Visual research workspace and V2 release proof

**Candidate:** ARES `0.11.0` / schema `0012`  
**Baseline:** supplied `ARES_M10_release_candidate(1).zip`, SHA-256 `02321335a16c3fa6ea6713cad5ee6bb964d76d899d54eadc8c400e01ec9079f7`; M11 is an additive continuation, not a rewrite.  
**Date:** 5 October 2026

## Implemented source scope

M11 continues to use the M07–M10 run, evidence, claim, asset, locator and assessment contracts. It does not introduce a second evidence store, graph database, executable chart language or model-side tool authority.

### M11-01 — research workspace information architecture

- Added stable research deep-link parsing for conversation/run/evidence selection while preserving the existing React/Vite application and API client.
- Added dedicated answer, source/evidence, comparison and activity workspace views instead of exposing worker internals as the default interface.
- Added evidence/source filtering and URL-restorable evidence inspection.
- Replaced the intentionally limited answer renderer with safe Markdown/GFM rendering that does not enable raw HTML.
- Preserved authenticated in-app document/media evidence navigation and added focus/keyboard-oriented behavior around evidence inspection.
- Added semantic light/dark theme tokens and retained reduced-motion handling.
- Heavy PDF, chart and evidence-graph modules remain separately loaded/bundled instead of being forced onto the initial search surface.
- Added SPA static-file fallback support for research deep links without weakening `/api/*` routing.

### M11-02 — evidence-linked visualizations

- Added migration `0012_visual_artifacts` with workspace-owned visualization datasets/artifacts and API-role read-only access.
- Added a restricted `VisualizationSpec`/dataset/lineage domain contract. Visualizations can reference only stored run evidence/claims/sources; arbitrary URLs, JavaScript, HTML, SQL, Python and executable model options are not accepted as visualization authority.
- Added deterministic visualization generation after successful research completion in the worker. Generation is idempotent and optional; visualization failure emits a durable degradation event without rewriting an otherwise completed research run as failed.
- Kept `GET /api/v2/runs/{run_id}/visualizations` read-only. The API does not lazily mutate state during a GET request.
- Added schema/readiness checks so visualization capability is not reported ready merely because a feature flag is enabled.
- Added comparison, numeric chart, source-publication timeline and bounded claim/evidence relationship views using the same persisted evidence lineage.
- Visualization CSV is now generated by an authorized server endpoint from the persisted approved dataset, carries evidence/source lineage IDs, uses private/no-store download headers, and escapes spreadsheet-formula prefixes. The browser no longer invents a second export representation.
- Numeric datasets reject mixed/incompatible units at the client boundary and preserve source/evidence IDs. CSV export escapes spreadsheet-formula prefixes.
- Evidence graphs are capped by configuration at 100 nodes / 200 edges and retain a non-graph/tabular evidence path.
- The current timeline is explicitly a **source publication timeline**. It does not claim to infer event dates, and it never substitutes retrieval time for an unknown publication/event date.
- Added `visualization.ready` / `visualization.failed` activity events and bounded frontend polling to reconcile the small race between terminal run state and post-run visual artifact publication.

## Security / correctness notes

- API reads remain authorized by the run/workspace boundary; the API DB role receives SELECT, not INSERT, on visualization tables.
- Worker generation is server-deterministic from finalized persisted research objects. Model output is not executed as chart configuration.
- Every visual numeric row keeps lineage; values without resolvable evidence are excluded rather than invented.
- Same-source derivatives are not represented as independent support merely because multiple visual rows exist.
- CSV values beginning with spreadsheet formula markers are escaped.
- Visualization readiness fails closed when schema storage is unavailable.

## Rollback

Set `VISUALIZATIONS_ENABLED=false` to hide optional visual artifacts while preserving answer/evidence/table functionality. Keep schema `0012` and immutable visualization lineage records; do not destructively downgrade evidence or claim provenance. Existing M10 answer, evidence, quality and export paths remain the compatibility fallback.
